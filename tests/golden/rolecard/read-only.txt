Class read-only (a barrier, not a sandbox):
- Read anything but the lead's keys; write only OUT and TMP (tool caches are not judged).
- Do not run the whole suite, only the checks that cover what you review.
- The report is OUT/report.md; if the file tool is refused, `qargi local report RUN < FILE` or `--from NAME` (it reads OUT only).
- To test patches, copy in TMP: `git -C TMP clone CLONE x` (a relative directory lands under -C: TMP/x), then `git -C TMP/x am OUT/NAME.patch`; or `cp -a CLONE TMP/x`. In the copy only push and remote changes are refused.
- Refused in CLONE: checkout, stash, apply, `git worktree add`, a clone or an init inside it.
- Read BASE with `git show BASE_SHA:PATH` and `git diff BASE_SHA`.
- Assign no variable that picks a program or options (PATH, HOME, TMPDIR, GIT_*, LD_*, BASH_*, PYTHONPATH, NODE_OPTIONS, ...; see `qargi help guard`). TMPDIR is TMP, where Go tests write. A target platform (GOOS, GOARCH) and `systemd-run` in TMP are allowed.
- A line, even in a heredoc, a quoted string or a commit message, that starts with git push, ssh or gh is refused: write such text with your file tool.
- Report a refusal's [code]; do not work round it.
