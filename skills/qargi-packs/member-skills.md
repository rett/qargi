# Managed member snapshots

`qargi packs member-skills PROJECT` reads status. `--enable` and `--disable` each print a plan; apply with its `--plan TOKEN --approved "<the person's words>"`. Choices are exclusive. Default absent/off keeps managed delivery absent. Disabling needs no new content or runtime qualification. Members cannot mutate this answer; project set/unset refuses its protected path.

Selection uses canonical user, user-role, project and project-role links for the actual role, minus that role's exclusions and incompatible packs. Broad user/project links intentionally reach every role; role-specific lead links reach no other role. Names carry no implicit lead-only metadata. Installed user skills, checkout files and rendered unions confer no snapshot authority. A client can independently discover committed skills or read other files under its existing contract.

The composed command runtime must declare `dispatch.home.skills_dir`, relative to its private home, with no credential, residue or configuration overlap. This is structural support; actual loading needs separate evidence. In-session delivery refuses. MCP admission stays under its existing policy; prose grants no permission.

Prepare freezes bounded nofollow copies in private lifecycle authority. A present nonempty matching approval hash and passing canonical review are mandatory, including for bounded support files. Empty selection yields a present empty snapshot. No symlinks, hardlinks, specials or unsafe paths. Bounds: 64 skills, 4096 entries, 2,000,000 bytes/file, 16 MiB total including records, 1 MiB manifest, 16 path components and 512 bytes/path. Canonical per-pack limits still apply. Full per-file SHA256s and normalized owner modes protect integrity separately from approval hashes. Top-level `.pack.json` stays private.

Dry-run reports destination, names and hashes read-only. Launch validates actual bytes, begins the lifecycle, then copies into `RUN/home/DIR/skills_dir`; finally it removes only proven-owned delivery directories. Foreign or replaced destinations, symlink traversal and missing ownership refuse without adoption. Retry restores the same snapshot or refuses. Saved generations preserve evidence; closed or cleaned runs cannot resurrect.

Opt-in, relevant links/scope/exclusions, content/approval or runtime/composition drift requires re-prepare. Unrelated project answers do not stale it. RUN mirrors cannot authorize anything. Old requests without snapshots remain valid when default-off inputs stay unchanged. Existing prepared-request exact definition/composition hashes remain unchanged: a shipped home declaration can stale an existing request, even with opt-in off. Re-prepare at that upgrade boundary; enabling after a no-snapshot prepare also refuses. No actual client loading is qualified by the hermetic fixtures.
