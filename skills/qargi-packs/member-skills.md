# Managed member snapshots

`qargi packs member-skills PROJECT` reads status. `--enable` and `--disable` each print a plan; apply with its `--plan TOKEN --approved "<the person's words>"`. Choices are exclusive. Default absent/off keeps managed delivery absent. Disabling needs no new content or runtime qualification. Members cannot mutate this answer through its public verb or helper. Project set/unset refuses its protected path; whole-file enabling or boolean changes refuse, while unchanged input and removal/narrowing remain supported.

Selection uses canonical user, user-role, project and project-role links for the actual role, minus that role's exclusions and incompatible packs. Excluded packs supply bounded compatibility facts for drift, never snapshot bodies or authority; missing approval or failing body review cannot gate their exclusion. Inclusion requires approval and review. Broad user/project links intentionally reach every role; role-specific lead links reach no other role. Names carry no implicit lead-only metadata. Installed user skills, checkout files and rendered unions confer no snapshot authority. A client can independently discover committed skills or read other files under its existing contract.

The enable plan inventories currently dispatchable known work roles, including library roles absent from project answers, excluding coordinator lead. It distinguishes invalid and unavailable metadata and binds the current inventory into recomputation. Project entries remain optional where prepare already accepts their absence. The plan does not freeze future roles: ordinary authorized prepare and current snapshot qualification still apply.

The composed command runtime must declare `dispatch.home.skills_dir`, relative to its private home, with no credential, residue or configuration overlap. This is structural support; actual loading needs separate evidence. In-session delivery refuses. MCP admission stays under its existing policy; prose grants no permission.

Prepare freezes bounded nofollow copies in private lifecycle authority. A present nonempty matching approval hash and passing canonical review are mandatory for included skills, including bounded support files. Empty selection yields a present empty snapshot. No symlinks, hardlinks, specials or unsafe paths. Validate linked kinds/names and skill count before body reads; apply entry/byte bounds cumulatively during collection. Bounds: 64 skills, 4096 entries, 2,000,000 bytes/file, 16 MiB total including records, 1 MiB manifest, 16 path components and 512 bytes/path. Canonical per-pack limits still apply. Full per-file SHA256s and normalized owner modes protect integrity separately from approval hashes. Top-level `.pack.json` stays private.
